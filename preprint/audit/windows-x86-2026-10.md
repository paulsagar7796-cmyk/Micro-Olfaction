# Independent reproduction on Windows x86-64, October 2026

An unsolicited third-party reproduction of the v3 preprint. The replicator saw the preprint
announced on social media, cloned the public repository and ran it on their own machine without
any contact beforehand. They sent back a bundle of logs and regenerated results on 2026-10-10.

Their raw bundle: `olfaction_repro_windows2.zip`, sha256
`57880f18d72649e5a38ef560a9c1a56844d58a4749a25c6f51328ef134f9c6d9` (4.7 MB; the 29 MB of
regenerated CSVs are not committed here, only the reports below).

Files in `windows-x86-2026-10/`: `environment.txt`, `run_all.log`, `check_reproduction.txt`,
`check_paper_numbers.txt`, exactly as received.

## Scope — what was and was not reproduced

**Regenerated and compared (14 files):** `tune`, `budget`, `sequential`, `literature`, `improve`,
`combine`, `confound`, `table`, `costs`, `pseudo_labels`, `presence` ×3, `energy`.

**Not regenerated.** The Cortex-M4 and C-port steps need the xPack Arm GCC and QEMU toolchain, which
was not installed, and the twin-array validation (`validation/reproduce_validation.sh`) was not run.
`check_reproduction.py` nevertheless prints `identical` for `device_reference.csv`,
`firmware_check*.csv` and `cm4_*.csv`, because those files were still the committed ones and were
compared against themselves. **Those verdicts carry no independent weight.** Perturbing the C-port
files drops `check_paper_numbers.py` from 96/155 to 78/155, so **18 of the 96 passing checks depend
on files this run never produced.**

So this run independently verifies the Python benchmark pipeline. It does **not** independently
verify the C implementation, the cycle/memory figures, or the twin-array validation.

## Result

| Outcome | Files |
|---|---|
| Bit-identical | `temporal_confound_file_order`, `temporal_confound_baseline` |
| Equal within 1e-9 (formatting only) | `presence_test`, `presence_test_nobias`, `presence_test_tracking` |
| Differ | `system2_tuning`, `system2_budget_sweep`, `sequential_system2plus`, `literature_comparison`, `system2_improvements`, `system2_combined`, `temporal_confound`, `literature_table`, `pseudo_label_scores` |

Every differing file is SGD-trained. The signature is a median difference of exactly zero with
occasional large bifurcations — the worst single cell is a `temporal_confound` entry at 0.140 here
against 0.912 there (setting 2, seed 42, "no labels"). Aggregates are stable: every
`average_6_10` column agrees within 0.5 points even where individual batches move by up to 4.5.

### Cause

Not nondeterminism, and not the worker count. Tested on our machine with `check_pseudo_labels.py`:

- 8 workers vs 4 workers: **bit-identical** (work is split per seed across processes)
- BLAS/OpenMP thread environment variables pinned to 1: **bit-identical**
- our 4-worker run vs their 4-worker run: differs, by exactly the same amount as before

The divergence is therefore deterministic platform arithmetic — a different ISA and a different
BLAS implementation producing different rounding in the same operations, which then sends
stochastic-gradient trajectories into different basins in unstable configurations. Matching the
pinned package versions cannot prevent this.

## Effect on the paper's claims

`check_paper_numbers.py` reports 96/155 on their results; we reproduced that figure exactly by
running our own checker over their files. Every one of the 59 failures is small.

Every table cell moves by at most 0.6 points, inside the reported seed spreads; the largest prose
deviation is 2.0 points on a range endpoint; two count claims shift by one (`3 of 5 seeds` to
`4 of 5`, `19 of 20` to `18 of 20`). No sign changes, no ordering changes between methods, and no
conclusion reversed. The headline margin is larger here than published, so the paper is conservative
on this platform.

The preprint's availability statement is already platform-qualified ("verified by the author ... on
an Apple silicon computer (Python 3.13.2, NumPy 2.2.6, ...)"), so nothing in it is contradicted by
this run and no correction to the published record is required.

## What this establishes

- The Python benchmark pipeline reproduces on a different operating system, CPU architecture and
  operator, from the public archive, with the paper's quantitative conclusions intact.
- Bit-identical reproduction requires the same platform, not merely the pinned package versions.

## What it does not establish

- Nothing about the C implementation, the Cortex-M4 cycle, energy or memory figures, or the
  twin-array validation; those steps were not run.
- It is not a from-scratch reimplementation: the same pinned library versions were used, so the
  software stack is shared.
- The replicator is so far anonymous, so a reader cannot yet check the provenance of this report.
